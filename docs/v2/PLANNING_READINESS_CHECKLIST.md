# V2 Planning Material: Planning Readiness Checklist

Not current runtime truth. Use this checklist before starting a new V2 planning slice.

## Purpose

- Confirm the repo has enough doctrine, evidence, and inventory context for the next docs-only planning step.

## Doctrine Readiness

- [ ] doctrine is separated from candidates
- [ ] permanent no-repeat rules are explicit
- [ ] current runtime canon is separated from V2 planning material
- [ ] one-public-gateway doctrine is easy to find

## Evidence Readiness

- [ ] major V1 lessons are summarized
- [ ] evidence categories are standardized
- [ ] historical references are not phrased as live direction
- [ ] retest-only items are separated from doctrine
- [ ] prep docs tell ChatGPT and Codex to keep current canon separate from planning synthesis

## Inventory Readiness

- [ ] Mini and Studio inventories are summarized
- [ ] Orin is explicitly pending
- [ ] HP is explicitly pending
- [ ] host/canon contradictions are visible

## Reconciliation Readiness

- [ ] current blockers are listed
- [ ] non-blocking unknowns are tracked
- [ ] no contradiction has been normalized into pseudo-canon

## Planning Boundary Discipline

- [ ] no backend/default selection has been made prematurely
- [ ] no repo-layout decision has been made prematurely
- [ ] no infrastructure design has been introduced
- [ ] no BMAD-specific planning has been added
- [ ] prep templates bias toward review/readiness sessions before infrastructure-shaped planning

## Open-Questions Discipline

- [ ] open questions are short and evidence-based
- [ ] weak evidence is marked weak
- [ ] candidate systems are not described as settled

## Not Planning-Ready When

- doctrine and candidates are mixed together
- host contradictions are hidden or hand-waved
- pending inventories are treated as completed
- prep docs drift into implementation planning
