# V2 Planning Material: Project Instructions

Not current runtime truth. These are planning-only instructions for a ChatGPT Project.

## Operating Boundary

- Use `docs/v2/*` as planning synthesis, not runtime canon.
- Use active platform, topology, integration, and service docs only when checking current runtime truth.
- Treat journals as evidence, not as live runtime instructions.

## Planning Rules

- Do not design V2 infrastructure here.
- Do not choose backends, models, or defaults.
- Do not decide repo layout.
- Do not propose host/service mutation.
- Do not assume Mini or Studio inventory is self-updating truth.

## Evidence Rules

- Every major claim needs repo evidence.
- Prefer durable lessons over chronology.
- Keep these categories explicit:
  - `doctrine`
  - `conditional candidate`
  - `historical reference`
  - `retest-only`
  - `unknown`
- If evidence conflicts, keep the disagreement visible.

## Output Rules

- Be concise and operational.
- Separate proven lessons from hypotheses.
- Call out open questions directly.
- Use the evidence categories explicitly when summarizing conclusions.
- Do not turn candidate systems into V2 identity by wording drift.

## Disallowed Outcomes

- LiteLLM rebuild plan
- MLX rebuild plan
- OpenHands expansion plan
- Orin or HP integration plan
- BMAD workflow plan

## Preferred First Uses

- planning-readiness review
- doctrine review
- evidence consolidation
- inventory reconciliation review
